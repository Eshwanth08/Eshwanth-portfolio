The problem

Design project workflows — from client intake to final delivery — are still manual, slow, and inconsistent. Requirements live in chat threads and calls, and they get lost in translation between what the client said and what the designer eventually builds. Everyone accepts this friction as normal. I don't think it has to be.

The approach

I'm architecting an end-to-end pipeline that automates that lifecycle: LLM-based requirement extraction converts raw client input into structured, unambiguous briefs, and MCP integration with Figma turns those briefs into first-draft layouts automatically. To keep it shippable, I scoped a phased MVP using MoSCoW prioritization — core modules first (project intelligence scoring, task generation, scheduling, client approval workflow), expansion later.

// Pipeline architecture

→
🧠LLM Extractionstructured briefs
→
🎨Figma Draftsvia MCP
→
✅Approval Flowclient sign-off

What I learned

On scoping — an ambiguous, multi-stage system taught me to break architecture into shippable phases instead of trying to build everything at once. On LLMs — working with model outputs means designing around unpredictability, not clean API responses: validation layers, fallbacks, and human checkpoints are part of the architecture.
